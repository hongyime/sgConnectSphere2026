Give unassigned sprint cells a clear label

Recommend displaying Unassigned when a canonical case has no sprint number, documenting the rule beside the testing catalogue, and generating every workbook from Markdown after team approval.

Data flow and current baseline

Keep the planning decision in the backlog and render its empty state only in the generated workbook.

Observed baseline: PROJECT TEST CASES CAA 141026.xlsx has 354 cases and 21 blank Sprint Number cells: E02-S05 (3), E02-S07 (5), E04-S02 (5), E07-S08 (4), and E10-S03 (4). The corresponding canonical story Sprint fields are blank in the current backlog; verify them again at implementation time.

02

Display choices and proposed rule

Select wording that says only what the backlog establishes: no sprint number is currently assigned. Do not imply that an assignment is approved or inevitable.

DisplayProsConsAssessment
UnassignedStates the current planning status directly; easy to search, filter, and understand outside the repository.Uses more column width and repeats across several rows.Recommended. Accurate without promising a future assignment.
— (em dash)Compact and visually distinct from an accidental empty cell.Can mean “not applicable,” “not provided,” or “not yet decided”; readers need a nearby legend.Acceptable only with an explicit legend.
TBDFamiliar shorthand and compact.Implies a decision is pending; a story may simply be outside current sprint planning.Not recommended; overstates intent.
Blank + notePreserves the current workbook values and numeric-only column.Blank cells remain ambiguous after a sheet is copied or separated from its note; filtering blanks can look like missing data.Lowest-change fallback, with weaker clarity.
Not scheduledClear to many readers and fits a planning report.Can sound like an explicit decision to exclude the story, which differs from “no sprint assigned.”Use only if the Product Owner confirms that meaning.

Where to document the rule

  • Primary explanation: add a concise “Sprint Number display” note to docs/testing/README.md, beside the dated workbook and Markdown authority guidance. State that empty Sprint metadata is displayed as Unassigned, and that this is not a new planning decision.
  • Implementation source: define one named display constant and a short comment in scripts/export_testcases_xlsx.py; do not duplicate the literal across branches.
  • Workbook context: the cell text itself should be self-explanatory. If users routinely receive the workbook without its README, optionally generate a comment on the “Sprint Number” header. Do not add a note row or hand-edit the export; keep the ten-column table shape intact.
  • Decision record: a display-only convention can live in the testing README and its reviewed PR. If the team changes actual sprint assignments or the meaning of a blank, record that planning decision in BDR Markdown and update backlog/Jira through the normal workflow.

Generator change

  1. In _parse_case_block, continue reading Sprint metadata. For empty or whitespace-only metadata, return the approved display constant instead of "".
  2. Keep assigned sprint values as they are today: numeric values stay numeric; non-numeric values keep current parsing behavior.
  3. Increase column A width from 10 to about 14 so Unassigned is not clipped.
  4. If the team selects a blank-plus-note option instead, keep blank cell output and generate the agreed header comment or legend through the script.

Do not put the word Unassigned into the canonical test-case Sprint metadata. The label is an export presentation value; planning data remains blank until a sprint is assigned.

Planned files

  • scripts/export_testcases_xlsx.py — map blank sprint metadata to the approved display and adjust width.

  • New dated workbook under docs/testing/PROJECT TEST CASES CAA <DDMMYY>.xlsx — regenerate from Markdown; never edit cells by hand.

Updating existing blanks

  • First re-check canonical backlog Sprint fields at implementation time. Do not make a sprint planning decision as part of a formatting change.
  • With “Unassigned” approved and the five assignments still blank, rerun the export so the 21 current cells display the label.
  • If any story has since been assigned, synchronize the case metadata from the canonical backlog and let the export show its numeric sprint value.
  • If the team chooses blank-with-note, keep the 21 cells blank and generate the note/legend; document that the blank is intentional.

03

Agreement and delivery sequence

  1. Confirm the meaning.

    The Product Owner or current backlog planning lead confirms that an empty Sprint means “no sprint assignment recorded.” Keep display choice separate from assigning the stories.

  2. Agree the label with catalogue owners.

    Review the options in the team’s backlog/refinement discussion with the test-case or workbook maintainer and the script maintainer. Recommend “Unassigned.” The team records its choice in the PR; a teammate reviews the code, tests, and generated workbook under the Definition of Done.

  3. Document and implement the approved convention.

    Update docs/testing/README.md, the export script, and focused tooling tests. If agreement changes sprint planning itself, handle that as a separate BDR/backlog/Jira update first.

  4. Regenerate and inspect the workbook.

    Use scripts/export_testcases_xlsx.py with the run date. Keep older dated exports as history; same-day regeneration may replace that date’s workbook. Confirm every empty source sprint is displayed consistently.

  5. Run repository checks and prepare review evidence.

    Run the focused exporter tests and python scripts/check.py, then have another teammate review. If verification is cited as PR, story-completion, or demo evidence, create one new T-65 run record; do not edit existing run records.

Approval owners: Product Owner/planning lead for the meaning of assignment state; test-case/workbook maintainer for course-export usability; engineering maintainer for generator behavior; one teammate reviewer for the resulting code and tests. No specific person is assigned by this plan.
