# E11 test cases

## E11-S01

### TC_E11S01_01 — Verify that a user linked to an event should be notified when its status changes or a booking decision is made, with details of what/when/which event

- **Sprint**: 2
- **AC reference**: E11-S01 - Scenario 1 (Status change notified)
- **Type**: 2 - Happy Path

#### Pre-conditions

organiser_a@clienta.com is linked to event "EVT-3001 Approved Annual Conference", currently "Under Review"

#### Test steps

1. As coord_a@connectsphere.com, approve request "EVT-3001 Approved Annual Conference" (status -> Approved)
  2. Log in as organiser_a@clienta.com and open notifications

#### Test data

Event: Annual Tech Summit | Change: Under Review -> Approved

#### Expected result

A notification is received stating the status changed to "Approved", the time of the change, and that it concerns "EVT-3001 Approved Annual Conference"

### TC_E11S01_02 — Verify that effective date, time or venue changes follow the approved recipient matrix

- **Sprint**: 2
- **AC reference**: E11-S01 - Scenario 2 (All affected parties notified)
- **Type**: 2 - Happy Path

#### Pre-conditions

Event "EVT-3001 Approved Annual Conference" the event has organiser_a@clienta.com, venue_a@connectsphere.com, and tech_a@connectsphere.com assigned, and attendee_a@example.com registered; attendee_b@example.com is waitlisted and coord_a@connectsphere.com is the assigned Coordinator

#### Test steps

1. As coord_a@connectsphere.com, change the event's venue
  2. Check notifications for organiser_a@clienta.com, venue_a@connectsphere.com, tech_a@connectsphere.com, and attendee_a@example.com

#### Test data

Changed field: Venue

#### Expected result

The Organiser, assigned Venue Staff, assigned Technical Support Staff, registered Attendee and waitlisted Attendee receive a notification. The acting Coordinator receives no self-notification. If another authorized actor or a system operation makes the change, the assigned Coordinator is included. Venue-move tests include responsible staff for both the old and new venues. Backend resolver fixtures are not evidence that the venue-assignment workflow is implemented.

### TC_E11S01_08 — Verify that an unreachable email provider does not affect the business change or the in-app notification

- **Sprint**: 2
- **AC reference**: E11-S01 · Scenario 5 (Delivered in-app and by email) · ADR-006
- **Type**: 4 - Negative (third-party unavailable)

#### Pre-conditions

Event EVT-2003 has an assigned Coordinator coord_a@connectsphere.com. The email provider endpoint is configured to an unreachable host so every SMTP attempt fails

#### Test steps

1. Sign in as Venue Staff and approve the pending venue booking for EVT-2003
 2. Confirm the booking status has changed
 3. Sign in as coord_a@connectsphere.com and open the notification list
 4. Inspect the delivery records for that notification

#### Test data

SMTP host: unreachable · Notification: venue booking approved

#### Expected result

The booking is Confirmed and the change persists. The in-app notification appears for the Coordinator. The email delivery row is marked failed with a recorded reason. The business transaction is not rolled back by the email failure

### TC_E11S01_09 — Verify that a rolled-back business transaction publishes no notification

- **Sprint**: 2
- **AC reference**: E11-S01 · Scenario 1 (Status change notified) · ADR-006 outbox guarantee
- **Type**: 4 - Negative (transaction rollback)

#### Pre-conditions

Event EVT-2004 is at status Under Review. A fault is injected so that the approval transaction fails after the notification delivery rows are written but before commit

#### Test steps

1. Sign in as the assigned Event Coordinator
 2. Approve EVT-2004, triggering the injected failure
 3. Re-read the event status
 4. Inspect the job queue and the Organiser's notification list

#### Test data

Event: EVT-2004 · Injected failure point: after delivery rows written, before commit

#### Expected result

The event remains at Under Review. No delivery row is persisted, nothing is published to the queue, and the Organiser receives no in-app notification and no email. Only committed deliveries are ever published

### TC_E11S01_16 — Keep uncommitted notifications invisible and roll back all writes

- **Sprint**: 2
- **AC reference**: E11-S01 - approved routing extension (T-64); ADR-006
- **Type**: 3 - Integration / regression

#### Pre-conditions

#### Test steps
