# E03 test cases

## E03-S01

### TC_E03S01_01 — Verify that submitting a request should trigger automatic assignment of exactly one Event Coordinator and move its status to Under Review

- **Sprint**: 2
- **AC reference**: E03-S01 - Scenario 1 (Exactly one Coordinator assigned)
- **Type**: 2 - Happy Path

#### Pre-conditions

organiser_a@clienta.com has a request "Annual Tech Summit" with all mandatory fields complete, ready to submit. At least one Event Coordinator account exists and is eligible for assignment

#### Test steps

1. Submit the request "Annual Tech Summit"
  2. Open the request and check the "Assigned Coordinator" field and status
  3. Log in as the assigned Coordinator and check their notifications

#### Test data

Request: Annual Tech Summit

#### Expected result

Exactly one Event Coordinator is assigned, the request status changes from "Submitted" to "Under Review", and that Coordinator receives a notification of the new assignment. Under BDR T-64 / E11-S01, the system-generated Under Review change also notifies the Organiser. The assigned Coordinator receives one combined assignment/status notice and one email-outbox row, not duplicate notices. Draft submission follows the same rule; an outbox failure rolls back the business change and audit

- **AC reference**: E03-S07 - Scenario 5 (Unassigned Coordinator refused)
- **Type**: 4 - Negative

#### Pre-conditions

Event "Annual Tech Summit" has status "Approved", assigned to coordinator_1@connectsphere.com. coordinator_2@connectsphere.com is not assigned to this event

#### Test steps

1. Log in as coordinator_2@connectsphere.com
  2. Open event "Annual Tech Summit"
  3. Attempt to edit any field

#### Test data

Acting user: coordinator_2@connectsphere.com (not assigned)

#### Expected result

The edit action is refused since coordinator_2@connectsphere.com is not the assigned Coordinator
