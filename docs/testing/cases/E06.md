and require the E06-S03/S04 workflows; evaluator/UI tests alone do not prove them.

2. Request C referencing B's rejection.
3. Reject C with suggestion D and request D referencing C.

### TC_E06S06_06 — Verify buffer-growth conflicts block approvals until an explicit resolution

- **Sprint**: 3
- **AC reference**: E06-S06 - Scenario 4 (Approval rechecks current buffered availability; T-100)
- **Type**: 3 - Integration / regression
- **Decision provenance**: T-100, PO interpretation dated 22 October 2026

#### Pre-conditions

Orchid Hall has setup and turnaround set to 0. Two Pending requests, Charity Run 10:00-12:00 and Alumni Dinner 12:00-14:00, were successfully accepted while their advertised windows were adjacent. Venue Staff then changes setup to 30 minutes and turnaround to 45 minutes.

#### Test steps

1. Confirm the buffer edit saves and both Pending rows remain; earlier Charity Run is unflagged and later Alumni Dinner has `buffer_conflict` true under the existing equal-status ordering.
2. Attempt approval of each request while the buffered conflict remains.
3. Resolve the conflict using one of these paths: (primary) Venue Staff reject one conflicting Pending request with a reason; (alternative) an authorized Coordinator withdraws/replans one request to a nonconflicting period and resubmits it as needed.
4. Approve the remaining now-free Pending request. For the alternative path, also approve the replanned request only if it is Pending and conflict-free.

#### Test data

Initially both buffers are 0. After the edit, Charity Run occupies 09:30-12:45 and Alumni Dinner occupies 11:30-14:45; these windows overlap from 11:30 to 12:45.

#### Expected result

Both approvals are refused while the conflict remains, and there is no automatic winner. Equal-status ordering leaves earlier Charity Run unflagged and sets `buffer_conflict` true on later Alumni Dinner. The primary resolution is for Venue Staff to reject one conflicting Pending request with a reason; that row becomes terminal Rejected, and the remaining still-Pending request can then be approved. Alternatively, an authorized Coordinator may withdraw/replan one request to a nonconflicting period; the remaining now-free Pending request and any valid replanned Pending request can then be approved. A Rejected row is never approved.
