# E04 test cases

## E04-S02

### TC_E04S02_01 — Creating one Session should support a single-session Event without extra lifecycle setup

- **Sprint**:
- **AC reference**: E04-S02 - Scenario 2 (Single-session event needs no extra setup)
- **Type**: 2 - Happy Path

#### Pre-conditions

An Event Organiser is creating an Event

#### Test steps

1. Add one Session with date, time, expected attendance, venue requirements, and equipment requirements
2. Save the Event

#### Test data

One Session: Opening | 2027-03-12 09:00–10:00 | 40 attendees

#### Expected result

The Event saves with one child Session; registration and lifecycle remain at Event level and no additional Event is created

### TC_E04S02_02 — Multiple Sessions should retain their own dates, times, attendance, and requirements

- **Sprint**:
- **AC reference**: E04-S02 - Scenario 1 (Sessions hold their own requirements)
- **Type**: 2 - Happy Path

#### Pre-conditions

An Event Organiser is creating a two-day Event

#### Test steps

1. Add Session A with its date/time, attendance, venue and equipment requirements
2. Add Session B with different values
3. Save and reopen the Event

#### Test data

Session A: 2027-03-12 09:00–11:00, 40 attendees, Hall A, projector | Session B: 2027-03-13 13:00–16:00, 120 attendees, Hall B, microphones

#### Expected result

Both Sessions remain children of one Event and retain their own distinct values

### TC_E04S02_03 — Venue suitability should use each Session’s own attendance and requirements

- **Sprint**:
- **AC reference**: E04-S02 - Scenario 3 (Suitability judged per Session)
- **Type**: 3 - Integration / regression

#### Pre-conditions

An Event has two Sessions with different attendance and venue requirements

#### Test steps

1. Search venues for Session A
2. Search venues for Session B
3. Compare suitability reasons

#### Test data

Session A: 40 attendees, step-free access | Session B: 120 attendees, theatre layout

#### Expected result

Each suitability result uses only the requirements and attendance for the Session being searched

### TC_E04S02_04 — The same venue may have separate bookings for different Sessions of one Event

- **Sprint**:
- **AC reference**: E04-S02 - Scenario 4 (Session booking is independent)
- **Type**: 3 - Integration / regression

#### Pre-conditions

One Event has two non-overlapping Sessions and the same venue is available for both

#### Test steps

1. Request the venue for Session A
2. Request the same venue for Session B
3. Review the Event’s bookings

#### Test data

Session A: 09:00–11:00 | Session B: 13:00–15:00 | Same venue

#### Expected result

Two distinct bookings are stored, each linked to its Session and time window; one does not replace the other

### TC_E04S02_05 — Deleting a Session should release its confirmed booking and retain history

- **Sprint**:
- **AC reference**: E04-S02 - Scenario 5 (Deleted Session releases its booking)
- **Type**: 3 - Integration / regression

#### Pre-conditions

Session A has a confirmed venue booking; Session B remains active

#### Test steps

1. Delete Session A
2. Check the venue calendar and event activity history
3. Check Session B

#### Test data

Session A booking: Confirmed | Session B booking: Confirmed

#### Expected result

Session A’s booking is released, Venue Staff are notified, and deletion is recorded; Session B and its booking remain unchanged
