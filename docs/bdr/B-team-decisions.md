| T-56 | One file per Vercel serverless API route, function count held at 11 | Vercel's file-based routing collapses `api/foo.ts` and `api/foo/index.ts` onto the same URL, and the build ships both lambdas without a warning. One silently wins the route; the other is an unreachable slot against the Hobby plan's twelve-function cap. PR #56 (SCRUM-26) added `api/events.ts` next to the pre-existing `api/events/index.ts` from PR #42 (SCRUM-18 hide internal planning info from Attendees, story E01-S03), which made `GET /api/events` return 405 in production for the whole of Sprint 1 and left the organiser browse-events screen backed by ClientEvents.tsx broken without anyone noticing. Adopting one file per URL with method dispatch inside the file eliminates the collision and returns a lambda slot; capping the file count at 11 keeps one slot of headroom so the next story does not land cap-blocked. Enforced by `scripts/check_api_routes.py` as a pre-commit hook and by `.pre-commit-config.yaml`. See ADR-014. | T-57 | A SCRUM-27 draft still requires title, dates and expected attendance | SCRUM-27 ("save an incomplete event request as a draft") does not say which of the ten mandatory fields may be left blank. `events.title`, `events.event_range` (the start/end date pair) and `events.expected_attendance` are `NOT NULL` with `CHECK` constraints in `backend/database/migrations/0001_connectsphere_schema.sql`; the other seven mandatory fields are already nullable columns. Making all ten skippable would need a migration relaxing those three constraints, with ripple effects on other modules (`venueBooking`, notifications, audit logs) that may assume every event row has a title, dates and an attendance figure — disproportionate for a 3-point story. Team decision: title, dates and expected attendance stay mandatory for a draft too, validated the same way as a full submission; the other seven skip the missing-field check while `status = 'draft'`. No migration. Confirmed by Aaron on 2026-09-18. | SCRUM-27 | - |
